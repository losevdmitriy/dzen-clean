Политика конфиденциальности

Дата редакции: 6 ноября 2026 года. Издатель и контакт для поддержки: Jonny Hills, hillsjonny86@gmail.com.

«Дзен Чисто» блокирует рекламные запросы и скрывает рекламные элементы обычных HTTP/HTTPS-страниц. Для этого расширение обрабатывает адреса запросов и структуру страницы локально в браузере.

Какие данные обрабатываются

  • Адрес текущего сайта, сведения о вкладке и сетевых запросах нужны для выбора правил и выключения защиты на выбранном сайте.
  • DOM и текстовые метки анализируются локально для распознавания рекламы. Содержимое страниц, писем, форм и история посещений не отправляются издателю и не записываются в журнал посещений расширения.
  • Локально сохраняются настройки, выключенные hostname, пользовательские исключения (hostname, путь страницы без query/fragment, CSS-селектор и цепочка Shadow DOM), фильтры, кеш, предыдущий комплект исправлений и состояние обновления. Исключения создаются пользователем явно.
  • Промежуточные сведения о вкладках и совпадениях фильтров используются в памяти. Статистика и автоматическая отправка отчётов в библиотеке отключены.

Сетевые обращения расширения

При включённом автообновлении расширение проверяет три фиксированных текстовых файла из официальных репозиториев RU AdList и AdGuardFilters на raw.githubusercontent.com при запуске и раз в шесть часов. Проверка также доступна по кнопке. Запросы выполняются без cookies авторизации и без Referrer. Сервер GitHub получает обычные сетевые сведения, например IP-адрес; к ним применяются условия конфиденциальности GitHub.

При обновлении самого расширения через каталог браузер обращается к службе обновлений Opera Add-ons; это штатная функция браузера. Локальные настройки и содержимое страниц издателю через неё не передаются.

Удалённые JavaScript и scriptlets из корректирующих списков не исполняются. Программные модули и полные статические базы поставляются новой версией расширения. У издателя нет сервера телеметрии; данные страниц, настройки и диагностические отчёты автоматически ему не отправляются.

Cookies и экспериментальные модули

В обычной конфигурации библиотеки отключены stealth и автоматическое старение cookies; разрешение на доступ ко всему хранилищу cookies браузера не запрашивается. Упакованные правила фильтрации могут использовать локальные scriptlets для рекламной логики страницы. Отдельный собственный модуль очистки фиксированного списка anti-adblock cookies работает только на Дзене и только после явного включения в экспериментальных настройках. Его список: blcrm, bltsr, zmFQeXtI, JPIqApiY, computer, KIykI.

Диагностика

По вашему нажатию «Скачать диагностику» создаётся локальный JSON с версией браузера/расширения, состоянием модулей и агрегированными счётчиками. В него не включаются посещённые hostname/URL, текст страниц, cookies, токены и CSS-селекторы исключений. Отправки нет. Если вы самостоятельно прикладываете отчёт к письму поддержки, его получает издатель вместе с данными, которые вы включили в письмо.

Хранение и удаление

Настройки и кеш остаются в профиле браузера до изменения, очистки данных расширения или удаления расширения средствами браузера. Автоматической синхронизации с аккаунтом издателя нет. Используемые разрешения ограничивают работу браузерными страницами; расширение не получает разрешения на чтение произвольных файлов компьютера.

Мы не продаём сведения о пользователях, не создаём рекламные профили и не передаём содержимое страниц аналитическим сервисам.

Privacy policy — English

Effective date: 6 November 2026. Publisher/support: Jonny Hills, hillsjonny86@gmail.com.

Dzen Clean processes request addresses, tab information and page DOM locally to select advertising filters and apply site exceptions. It does not transmit page content, emails, form text, browsing history, settings or diagnostic reports to the publisher automatically. It does not maintain a browsing-history log.

Settings, disabled hostnames, explicitly created page exceptions (hostname, path without query/fragment, CSS selector and shadow-host chain), filters, update state, cached corrections and their previous version are kept locally in the browser profile. They remain until changed, cleared or removed through the browser. Temporary tab/filter state is held in memory. Library statistics and telemetry are disabled.

When automatic correction updates are enabled, three fixed text files from the official RU AdList and AdGuardFilters repositories are checked on raw.githubusercontent.com at startup and every six hours. Manual checking is also available. Requests omit authentication cookies and Referrer; GitHub still receives ordinary connection information such as the IP address. Remote JavaScript/scriptlets are not executed. Program modules and full static filter bases are bundled with extension releases. The browser may contact the Opera Add-ons update service to update the extension itself; local settings and page content are not sent to the publisher through that service.

The cookie-controller/stealth ageing features of the filtering library are disabled, and no browser-wide cookies API permission is requested. Packaged filtering scriptlets may operate on the advertising logic of a page. A separate Dzen-only experimental module clears the fixed anti-adblock cookie names listed above only when explicitly enabled.

A diagnostic JSON is generated locally only on request. It contains versions, module state and aggregate counters, excluding visited hostnames/URLs, page text, cookies, tokens and exception selectors. If you voluntarily email a report to support, the publisher receives the information you chose to send and uses it to answer your request. Do not send credentials or private content.

No user profiling, data sale or page-content analytics service is used. Code is distributed under GNU GPL version 3 with third-party notices preserved. To ask a privacy or support question, contact the address above.
